## How this manifest is maintained and checked

- The inventory below is generated by `scripts/compute_manifest_hashes.py --update` from the
  classification table in that script, after all other edits are final.
- `python -B scripts/compute_manifest_hashes.py` (read-only, nonzero on failure) checks that:
  every file on disk is classified and listed exactly once; no listed file is missing; every
  checksum matches the current bytes; every git-tracked M3 file exists; and every protected
  artifact is byte-identical to the preservation baseline.
- Protected artifacts are all files tracked at the baseline except those this correction was
  authorised to edit (`README.md`, `MANIFEST.md`, `results/m3_a2g_data_verification.json`,
  `scripts/m3_a2g_data_verification.py`, `scripts/acceptance_checklist.py`,
  `scripts/compute_manifest_hashes.py`), plus the tracked historical patch outside this directory,
  `benchmarks/audit/v0.8.3-corrections-historical.patch`.

from `/tmp` (`sys.path.insert(0, '/tmp')`). That file is not in the repository, so these

## Diagnostic limitations

1. **`scripts/m3_a2g_ninit_sensitivity.py`: INVALID for robustness claims.** The fitter reseeds
   on every inner start, so all n_init > 1 runs use identical random initialisations. Its CSV is
   preserved; `best_converged` counts describe recorded output only.
2. **`scripts/m3_a2g_stopping_criterion_validation.py`: INVALID for validation.** The relative
   tolerance branch is unimplemented (falls through to tol = 1e-20); `convergence_iter` is an
   approximation (`2000` or `1900`); the continuation endpoint is not the stopping point.
3. **`scripts/m3_a2g_extended_maxiter.py`: VALID BUT UNPAIRED.** Seeds are `1000 + row index`,
   so each max_iter value sees different draws.
4. **`scripts/m3_a2g_monotonicity_check.py`: VALID BUT LIMITED.** Four fixtures; empirical, not a
   proof.

See [M3_A2G_CORRECTIONS_PROVENANCE.md](M3_A2G_CORRECTIONS_PROVENANCE.md).

## Provisional O2 classification

```
U — numerical-ceiling local-EM heuristic.
O2 — FUNCTIONAL BUT FRAGILE, provisional.
Optimization fragility documented;
initialization and stopping validation incomplete;
statistical robustness unresolved.
Not production-ready; no validated production defaults.
```

Required before any O3 consideration: fix the initialization diagnostic (independent per-start
seeds), fix the stopping validation (implemented relative tolerance, exact continuation), and
re-execute both. Required before production use: dependent-toroidal validation, a U/C/P
regularisation decision, q = 1 and q = 5 validation, temporal-correlation sensitivity and
calibrated significance testing.

The verification tooling checks data format, bookkeeping and provenance only. It does not change
this classification.
