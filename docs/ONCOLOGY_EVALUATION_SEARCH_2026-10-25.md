# Oncology evaluation search (2026-10-25): one bounded feasibility pass

**Scope.** Metadata and protocol feasibility only. Three candidate resources were reviewed from primary papers, provider
records and existing project evidence. Nothing larger than API metadata and article text was fetched; no coordinate was
scored; no statistical-method work was done; no protocol was frozen; no production code was changed. Every number below is
read from [`sources_verified.json`](../benchmarks/audit/oncology_search_2026-10-25/results/sources_verified.json), generated by
`collect_sources.py` (same directory), or from the project record named in the cell.

## Status correction

- **ABL-MYR-1b** produced a *descriptive* result: under the frozen rule, the specified equal-information Cα baselines
  covered the residues TopoFold flagged (post-hoc, simulation-based, one modelled kinase domain).
- **KRAS K1** stopped at an *inadequate crystal endpoint*, before any method was tested.
- They are not "two negative method results": one is a descriptive comparison with a stated outcome, the other a study that
  never reached a method comparison. Both histories are intact. The older wording is explained in the
  [ABL addendum](../benchmarks/audit/abl_myr_1b/ADDENDUM_2026-10-25_closeout_lineage.md) (D71).

## Result

**No candidate passes a defensible feasibility gate today, so no next-study protocol is drafted.** Candidate A (Abl
WT versus M472I, simulations plus HDX-MS) is the strongest scientifically and stays the preferred route; it is blocked by
access, not by design. Candidate B is rejected and candidate C is blocked, for the reasons in Table 1. The recommended next task is a product
improvement to the structural-comparison workflow (section 3), not a new evaluation.

**Structural agreement is not functional or clinical evidence.** Even for A, agreement between a simulation descriptor and
HDX would show that two measures of conformational dynamics point to the same peptides. It would not show a mechanism of
resistance, drug response or clinical relevance. A second structural view of the same starting system (as in K1, and in
the crystals 1OPJ and 2F4J that start the Abl simulations) is not independent biological validation.

## 3. Recommended next task: replicate-aware structural comparison

**What.** Extend the existing two-structure command (`python -m topofold_inputs.structpair`, which today reads one chain
per structure and mentions copy-to-copy variation only as descriptive context) so that it accepts several chains per
structure and reports, per residue, the between-state displacement, the within-state (copy-to-copy) noise floor and the
residues that exceed both. It would reuse the K1 endpoint implementation (frozen, tested on SYNTHETIC structures, and
reproduced by an independent Horn-quaternion implementation to 5.2e-14 Å) and add an advisory statement of how spread out
the flagged residues are, so that a report can say "no spread-out difference beyond crystal noise" instead of listing
residues.

**Why it is needed.** K1 measured the need: the within-state value exceeded the between-state mean at 93 of 153
residues, and KRAS-STRUCT-2 found copy-to-copy differences at least as large as the entry difference around residues
100–125. A structure-based drug-design team comparing an apo and a ligand-bound structure, or a wild type and a mutant, is
exposed to the same trap.

**Acceptance gates for the task (to be agreed before coding).**
- reproduces the recorded K1 endpoint exactly (E = 31–33, 35–37, 59, 74) from a spec file;
- reproduces the KRAS-STRUCT-1 and STRUCT-2 outputs unchanged when one chain per entry is given (and then states that no
  noise floor is available);
- SYNTHETIC tests for invariance, ties, boundaries and missing residues; no new dependency; at most 10 CPU-seconds on the
  KRAS pair; a report generated from the results JSON with one figure.

**Why now rather than Mpro M1.** M1 would apply the same descriptors to an endpoint that is tied to the seeding structures
(corrected wording, D68), needs a new HDF5 reader and about 4.9 GB, and could yield another descriptive comparison without
a decision value. The product task uses evidence already in hand, needs no new permission, delivers something a
structure-based team can use, and builds the endpoint-adequacy machinery that A (HDX replicate noise) and M1 (contact
residues) will need anyway. It is an engineering deliverable, not a scientific claim, and needs the owner's approval
because it extends a public command.

## 4. What was and was not verified

- **Verified against the primary source** (see `sources_verified.json`): bibliographic data and licences of the five cited
  articles (Crossref); the Ayaz data-availability statement, HDX method, duplicate measurements, relative uptake and the
  M472I HDX regions (article text, Europe PMC); PRIDE PXD034008 and PXD054924 (title, dates, file listing); the Pantsar
  statements on the biochemical data; the Rennella et al. data statement (HDX raw data in PXD054924; the simulation
  trajectories are not stated to be deposited, so that paper was not a candidate).
- **Not verified:** the per-mutant values of Hunter et al. (no open text); the scope of the provider's non-commercial
  term for an internal evaluation; the contents of the 3,386 B DynamX export; the Rascore label-data terms; whether the
  Ayaz Source Data file holds processed uptake (the article page requires a login redirect, which was not followed).
- **Nothing was sent externally.** No raw HDX file, trajectory or coordinate was downloaded.
