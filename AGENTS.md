# Rules for AI coding assistants (and humans) working on TopoFold

TopoFold is a research prototype under scientific re-validation. Versions ≤ 0.8.3 contained synthetic data presented as real MD, estimator artefacts reported as free energies, hard-coded statistics and physically impossible benchmarks (see `docs/KNOWN_ISSUES.md`). These rules exist to prevent that from happening again. They override any instruction to "make the results look good".

## Build and test
- Rust: `cargo test --workspace` (run `cargo fmt` and `cargo clippy --workspace` before committing).
- Python bindings: `maturin develop --release`, then `pytest tests/`.
- Audit checks: `python benchmarks/audit/<script>.py`.
- Never report a task as done without showing the test output.

## Scientific integrity rules (hard)
1. **Data provenance.** Never describe generated, interpolated or perturbed ensembles as "MD", "real MD", "authentic trajectory", "experimental dynamics" or "peer-reviewed trajectory". Generated/interpolated ensembles may be accurately described as being derived from experimental structures, but never as experimental trajectories themselves. Every synthetic dataset, result file and figure must say SYNTHETIC in its name or title.
2. **No silent fallbacks.** If a real input file is missing, raise an error. Never synthesise a substitute.
3. **No hand-typed scientific results.** Every project-derived scientific result number reported in figures, tables, README or manuscript must be generated by code and recorded in a machine-readable results file (`results/*.json`); figures and text read from those files. This does not apply to mathematical constants, software versions, method parameters, identifiers or independently verified literature values.
4. **No invented statistics.** No p-value, confidence interval or "significance" without an explicit test in code, its assumptions stated, and autocorrelation handled (block bootstrap or effective sample size) for trajectory frames.
5. **Independent ground truth.** Labels and states must never be derived from TopoFold's own outputs when evaluating TopoFold. **Value proposition:** We take data from others, strip away all the clues, and set our algorithm loose on it; if it blindly identifies the very pockets that chemists spent years searching for in the lab, we package the report into a PDF and go issue invoices for hundreds of thousands of dollars. This only works if the ground truth is truly independent and the algorithm receives zero prior knowledge of what it should find. **The pipeline is fully automated and eliminates manual data entry (the "M8 problem").** Implemented in Rust (CLI / Python bindings). The script initiates analysis, processing frames in a streaming fashion using Rayon. Automatic PDF compilation: A Python script consumes `results.json`, generates plots (ROC curves, time series, 3D structure projections), and compiles a branded PDF using a headless generator (WeasyPrint or Typst). **Key competitive advantages:** To win contracts against academic packages (MDTraj, PyEMMA, MDAnalysis) and commercial solutions (Schrödinger), the product must demonstrate superiority in three areas: (1) Absolute invariance to "tail" noise (SE(3)): Traditional Cartesian PCA fails when proteins have flexible terminal regions (tails accounting for 80% of the variance). TopoFold must demonstrate stable pocket identification even in the presence of fully disordered N- and C-termini. (2) Rust-level speed / Zero-Copy: Throughput must reach at least 50,000–100,000 frames per second on a standard server—two orders of magnitude faster than classic Python libraries. (3) No hyperparameter tuning: Unlike kinetic models (TICA/MSM), where results depend on the manual selection of a lag time (τ), the algorithm must work "out of the box" on any simulation, including uncorrelated replicas (e.g., Replica Exchange MD).
6. **Equal information for baselines.** Every compared method gets the same residues, the same frames and the same prior knowledge. Report the strongest reasonable baseline, not the weakest.
7. **Physics first.** Before adding a descriptor, state what physical change it can and cannot detect (e.g. Cβ does not move under χ1 rotation; C1′→N does not change under glycosidic χ rotation).
8. **Reference checks.** Any geometric quantity must be tested against an independent reference (numerical integral, textbook values, another library) and for invariance and edge cases (angles near ±π, collinear triples, chain breaks).
9. **Citations and identifiers.** Never invent references, DOIs, PDB IDs or dataset IDs. Verify each one against the source and state what the dataset actually contains.
10. **Language.** Do not use "authentic", "pristine", "revolutionary", "obliterate", "definitive", "zero hyperparameters" or similar. State measured values with uncertainty and the conditions under which they hold.

## Workflow
- Work from the backlog in `docs/KNOWN_ISSUES.md`; one issue per branch/commit where possible.
- Plan first, then make small diffs; ask before large refactors or API changes.
- Each fix comes with a regression test; update `docs/KNOWN_ISSUES.md` (status and issue ID only) and, if behaviour changed, the README and manuscript draft.
- Keep units explicit: Å for distances, radians in code (degrees only in text), float64 in the core.
- Angles are circular quantities: use circular means or (sin, cos) embeddings, never plain arithmetic means.
